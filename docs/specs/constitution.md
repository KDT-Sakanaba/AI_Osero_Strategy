# Constitution（プロジェクト共通原則）— REIGN OF DISCS

- 最終更新日: 2026-11-10
- 既存ルールとの関係: リポジトリに `CLAUDE.md`・`.claude/rules/` はまだない。原典は `docs/REIGN_OF_DISCS_ゲーム仕様書.docx`（v1.0。テキスト抽出版: `docs/GAME_SPECIFICATION_source.txt`）。本書は原典 19章・21章をこのプロジェクトの原則として要約したもので、原典と矛盾した場合は、原典の「仕様確定時の注意事項」に従って `spec.md` で確定した内容を優先する。

## 1. 開発原則
- 原典を正式な開発基準とする。記載内容を独断で削除・変更しない。矛盾や問題は実装前に問題点と改善案を示し、ユーザーの決定を `spec.md` の確認履歴に残す。
- 原典の Phase（1〜7）単位で小さく実装する。現在の Phase（feature）が完了条件を満たすまで次へ進まない。各段階で「実装 → ビルド → 動作確認 → 完了条件との照合 → 記録」を行う。
- 一度に大量のコードを生成しない。常にコンパイル可能な状態を保つ。
- 原典にない機能（20章「将来の拡張案」、付録B、セーブ・ロード、地形効果など）は先行実装しない。必要と判断した場合は提案に留める。
- 「オセロの面白さを損なわずにストラテジー要素を成立させる」（原典21章）を、迷ったときの判断基準にする。

## 2. 設計方針
- 通常オセロのルール処理（盤面・合法手・反転）と、ストラテジー拡張（資源・施設・能力・防御）を分離する。通常オセロモードの結果が、ストラテジー側のコードの有無や変更で変わらないようにする。
- `Board`（状態保持・変更）と `MoveValidator`（合法手判定・反転対象取得）を分ける。合法手判定と反転処理は同じ探索結果を使う。
- ゲームロジック（盤面・ターン・資源・施設・能力・AI）は DXライブラリに依存させない。描画・入力・音声・シーン管理だけが DXライブラリを呼ぶ。これにより、ロジックを DXライブラリなしでテストできるようにする。
- UI とゲームロジック、盤面処理と描画処理を分離する。外部から盤面配列を直接書き換えず、`Board` の関数を通す。
- 定数は `Constants.h` などにまとめ、マジックナンバーを避ける。不要なグローバル変数を使わない。同じ処理を重複させない。
- 将来の拡張（盤面サイズ・勢力・勝利条件・地形）を妨げない形にするが、拡張そのものは作らない。

## 3. 品質基準
- 完了とする最低ライン: (1) Visual Studio で Debug・Release の両方がエラー・警告レベル4の新規警告なしでビルドできる、(2) ロジックテスト（DXライブラリに依存しないテスト用実行ファイル）がすべて成功する、(3) 受け入れ条件のうち手動確認が必要な項目を、ユーザーが実際に確認している。
- 不正な操作（盤面外座標・配置不可マス・資源不足・建設不可マス・能力の不正使用・合法手なしの AI・画面遷移時の入力残留）でクラッシュしない。不正な操作では状態を一切変更しない。
- DXライブラリのリソース（画像・音声・フォント）は、取得したものを必ず解放する。
- AI は不正な手を選ばない。思考時間の上限（HARD: 2秒）を守る。
- 未実装・未確認の機能を実装済み・確認済みとして報告しない。

## 4. 禁止事項
- DXライブラリ以外の外部ライブラリ（テストフレームワーク・JSON ライブラリなど）を追加しない。
- 独自の Windows API による描画システムを作らない。描画・入力・画像・音声は DXライブラリの標準 API を使う。
- 正常に動作している機能を、変更理由を明示せずに変更しない。変更後は関連機能の回帰テストを行う。
- ユーザーの指示なしにコミット・push・外部への送信を行わない。

## 5. 対象ごとの追加原則
- 進捗の記録先: 実装タスクの状態・再開メモは各 feature の `tasks.md` を正とする。原典 19.6 の3ファイルは次の役割に限定し、tasks.md の内容を写さない。
  - `PROJECT_STATUS.md`: 現在の feature・Phase と、その tasks.md へのリンクだけ。
  - `IMPLEMENTATION_LOG.md`: 日付ごとの実装内容と変更ファイル（作業履歴）。
  - `KNOWN_ISSUES.md`: 既知の不具合と未解決事項。
